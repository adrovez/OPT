1. Resumen Ejecutivo

El sistema OPT para Ópticas está desarrollado en .NET Framework 4.8 con ASP.NET MVC 5, Entity Framework 6 y SQL Server. Su arquitectura monolítica limita la escalabilidad, el acceso remoto seguro y la incorporación de nuevas funcionalidades.

Esta propuesta define la hoja de ruta tecnológica para transformar OPT en una plataforma SaaS multi-empresa y multi-sucursal construida sobre:

  • API REST en .NET Core 10 con Clean Architecture
  • Frontend reactivo en Angular 19 con Signals
  • Base de datos SQL Server rediseñada: FK formales, multi-tenant, auditoría completa
  • Autenticación JWT + Refresh Tokens y control de roles granular
  • Inteligencia Artificial (Microsoft Semantic Kernel + Claude API) para asistencia en recetas, inventario y reportes
  • Integración mejorada con Defontana (ERP contable chileno)

La migración se plantea en 4 fases iterativas de 24 semanas, manteniendo el sistema legado operativo durante todo el proceso.

4. Rediseño de la Base de Datos

4.1 Principios del Nuevo Modelo

  • Multi-tenancy — columna TenantId en todas las tablas de negocio
  • Foreign Keys explícitas con ON DELETE / ON UPDATE correctamente definido
  • Renombres semánticos — OPT_Cliente → OPT_Paciente y OPT_Empresa → OPT_ClienteEmpresa
  • Eliminación de OPT_EmpresaSucursal — relación empresa/sucursal manejada directamente en OT
  • Catálogos — estados de cuota pasan de varchar a tabla OPT_EstadoPago
  • Auditoría estándar — CreatedAt, UpdatedAt, CreatedBy, UpdatedBy, IsDeleted (soft delete)
  • PK unificada — OPT_Paciente obtiene PK int autoincremental; RutPaciente queda como campo único
  • Índices en columnas de búsqueda frecuente: RutPaciente, idOT, idSucursal, FechaAtencion

4.3 Estrategia de Migración de Datos

  1. Script de limpieza: normalizar estados varchar, purgar registros sin referencia válida
  2. Crear nueva BD OPT_v2 con esquema modernizado (EF Core Migrations)
  3. Script Python/SSIS de migración con transformación: RUT → PacienteId (int) + RutPaciente (campo único)
  4. Período de ejecución paralela: ambas BDs activas durante las pruebas
  5. Validación de integridad: conteos, saldos totales, historial de OTs
  6. Cutover con ventana de mantenimiento máxima de 2 horas

5.2 Seguridad y Autenticación

  • JWT Bearer Tokens con expiración corta (15 min) + Refresh Tokens (7 días)
  • Roles: SuperAdmin, AdminTenant, Supervisor, Cajero, Vendedor, SoloLectura
  • Policies basadas en Claims: por sucursal, por empresa, por módulo
  • Rate Limiting por IP y por tenant (ASP.NET Core Rate Limiting)
  • HTTPS obligatorio, CORS configurado por tenant
  • Contraseñas con BCrypt; datos de recetas cifrados en tránsito y reposo
  • Auditoría de accesos en OPT_AuditLog
