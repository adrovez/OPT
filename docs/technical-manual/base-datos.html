Base de datos: dbOPT 11 tablas Soft-delete en todas Multi-tenant

Resumen

La base de datos dbOPT está en SQL Server 2022 (compatible con Azure SQL). Toda la evolución del esquema se gestiona con scripts SQL numerados en src/basedatos/. No se usa Entity Framework Migrations.

Regla multi-tenant: Todas las tablas de negocio tienen columna TenantId. Nunca hacer consultas sin filtrar por TenantId. Un error aquí expone datos de otros clientes.
Convención de tipos de PK: Las tablas de negocio (tenant-aware) usan UNIQUEIDENTIFIER DEFAULT NEWSEQUENTIALID() como PK y FK. Se usa NEWSEQUENTIALID() (no NEWID()) para evitar fragmentación del índice clustered. Los catálogos compartidos (OPT_Region, OPT_Comuna) mantienen INT IDENTITY. Ver ADR: .agents/decisions/2026-05-08-migracion-pk-guid.md

Guía: Agregar un Nuevo Script

Pasos para agregar cambios de esquema. Próximo número disponible: 015_.

-- Nombrar: 015_descripcion.sql
-- Siempre: USE [dbOPT]; GO

-- Para tablas nuevas: verificar existencia
IF OBJECT_ID('[dbo].[OPT_NuevaTabla]', 'U') IS NOT NULL
    DROP TABLE [dbo].[OPT_NuevaTabla];
GO

-- Para ALTER TABLE (incrementales): verificar columna
IF NOT EXISTS (
    SELECT 1 FROM sys.columns
    WHERE object_id = OBJECT_ID('OPT_Cliente')
    AND name = 'NuevaCampo'
)
BEGIN
    ALTER TABLE [dbo].[OPT_Cliente]
    ADD [NuevaCampo] NVARCHAR(100) NULL;
END
GO
Buenas prácticas: Usar SYSUTCDATETIME() para timestamps (UTC, alta precisión). Incluir siempre los campos de auditoría. Datos de catálogos con guards IF NOT EXISTS.
