Descripcion general

Una Orden de Trabajo (OT) es el documento comercial central de una optica. Registra los trabajos encomendados a un laboratorio o al taller interno (cristales, monturas, lentes de contacto, etc.), su estado de fabricacion y los datos de facturacion y cobro.

Cada OT tiene:

  • Un numero de OT ingresado manualmente (generalmente el numero del laboratorio), unico por tenant.
  • Un paciente (Cliente tipo Persona) y, opcionalmente, una empresa facturadora (Cliente tipo Empresa).
  • Lineas de productos/servicios del catalogo con precio libre.
  • Un abono inicial opcional y pagos posteriores ilimitados.
  • Un plan de cuotas opcional generado sobre el saldo al crear la OT.
  • Una bitacora inmutable de cambios de etapa fisica.
  • Vinculo opcional con una Atencion y/o RecetaCristales.
Acceso al modulo: Menu lateral → Clinica → Ordenes de Trabajo (/ordenes-trabajo). Requiere JWT valido y sucursal activa seleccionada.

Flujo de trabajo

Etapas de la OT (EtapaOT)

Ingresado → EnProceso → Montaje → Laboratorio → Calidad → Despacho → Entregado

El backend valida que el valor de EtapaOT sea uno de los 7 permitidos (constraint SQL CK_OPT_OT_EtapaOT). No existe una maquina de estados estricta: se puede avanzar o retroceder libremente entre etapas. Cada cambio genera un registro en OPT_OrdenTrabajoBitacora.

Estado de pago (EstadoPago)

ValorSignificado
PendienteSaldo > 0. Estado inicial.
PagadoSaldo = 0. El repositorio lo establece automaticamente al registrar un pago que liquida el saldo.

PUT /api/ordenes-trabajo/{id}

PUT /api/ordenes-trabajo/{id}

Actualiza la OT. Las lineas se reemplazan completamente (soft-delete de las anteriores + INSERT de las nuevas). Los abonos se reemplazan de igual modo. El campo SucursalId no cambia.

El body es identico al de creacion excepto que no incluye atencionId ni recetaCristalesId (esos vinculos no se editan).

Response 204: No Content.

Response 404: OT no encontrada.

Response 409: NumeroOT ya existe en otro registro del tenant.

DELETE /api/ordenes-trabajo/{id}

DELETE /api/ordenes-trabajo/{id}

Soft-delete de la OT (IsDeleted = true). La bitacora queda intacta.

Response 204: No Content.

Response 404: OT no encontrada.

Response 409: Regla de negocio que impide eliminar (ej. ya entregada — depende del validator).

POST /api/ordenes-trabajo/{id}/pagos

POST /api/ordenes-trabajo/{id}/pagos

Registra un pago posterior a la creacion de la OT. Actualiza TotalAbonado y Saldo de la cabecera. Si el saldo resultante es 0, cambia EstadoPago a Pagado automaticamente.

Request body

{
  "formaPagoId": 2,
  "monto":       100000,
  "fechaPago":   "2026-06-12",
  "observacion": "Saldo cancelado"
}

Response 200: { "pagoId": "uuid" }

Response 400: Monto invalido o datos faltantes.

Response 404: OT no encontrada.

Componentes

ordenes-trabajo-list

Tabla paginada de OTs. Filtros por N°OT, Etapa y EstadoPago. Badges de color por etapa (ETAPA_COLORS). Acciones: ver / editar / eliminar con confirmacion SweetAlert2.

orden-trabajo-form

Formulario crear/editar. Autocomplete de cliente y producto con debounce RxJS (300ms). Lineas dinamicas con subtotales en tiempo real via computed signals. Abono inicial multiple. Cuotas opcionales. Verificacion asincrona del N°OT.

orden-trabajo-detail

Vista de detalle en 2 tabs: Informacion (datos, lineas, pagos, cuotas, bitacora) y Atencion/Receta (lazy). Modales inline para cambiar etapa y registrar pago posterior.

Notas tecnicas

Header X-Sucursal-Id

El header X-Sucursal-Id es obligatorio al crear una OT (POST). En los demas endpoints es opcional — si se envia, filtra los resultados por sucursal; si se omite, devuelve OTs de todas las sucursales del tenant.

El frontend lo adjunta automaticamente desde SucursalContextService.sucursalActual()?.sucursalId en el metodo privado headers() del servicio.

Sin X-Sucursal-Id en POST → 400 Bad Request: el controller verifica el header antes de enviar el command y retorna un ProblemDetails con title: "Header requerido".

Calculo de montos

El repositorio calcula y persiste los montos al crear o editar:

SubTotal    = SUM(linea.Cantidad * linea.ValorUnitario)
MontoTotal  = SubTotal - Descuento
TotalAbonado = SUM(abono.Monto)
Saldo        = MontoTotal - TotalAbonado
EstadoPago   = Saldo <= 0 ? "Pagado" : "Pendiente"

Al registrar un pago posterior (POST /{id}/pagos), el repositorio actualiza TotalAbonado, recalcula Saldo y actualiza EstadoPago si corresponde.

Generacion de cuotas

Si NumeroCuotas > 0 y FechaInicioCuotas esta informada, el repositorio genera automaticamente el plan al crear la OT:

ValorCuota(n) = ROUND(Saldo / NumeroCuotas, 0)
// La ultima cuota absorbe el residuo del redondeo.

FechaVencimiento(n) = FechaInicioCuotas.AddMonths(n - 1)
Estado inicial de cada cuota = "Pendiente"

La gestion del cobro de cuotas (marcar como Pagada, registrar FechaPago) es parte del modulo de Caja, pendiente de implementacion.
